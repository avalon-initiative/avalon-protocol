# For Stakeholders

Documentation written for people evaluating Avalon from the outside — whether
this is worth backing, partnering with, or building a game, app, or service against — rather
than people writing code against it or contributing to it.

Start with:

- [`../WhyAvalon.md`](../WhyAvalon.md) — the case for why this needs to
  exist, and why it hasn't been built yet despite the idea not being new
- [`Proposal.md`](Proposal.md) — the full product overview: what Avalon is,
  the problem it solves, how it's structured, its guiding principles, and an
  honest list of current limitations, known challenges, and open questions

The normative architecture reference lives at
[`../projects/backend-server/architecture/`](../projects/backend-server/architecture/README.md)
if a technical evaluation needs the invariants rather than the narrative.
